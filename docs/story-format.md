# 剧本格式

一个游戏就是一个 `games/<id>/story.js`，里面只有一个 `const STORY = {...}`。
不需要 import，不需要构建配置，页面会自己加载它。

---

## 整体结构

```js
const STORY = {
  meta:   { ... },   // 标题等
  stats:  [ ... ],   // 数值条
  start:  'a1',      // 起始节点 id
  nodes:  { ... },   // 所有节点
};
```

---

## meta

```js
meta: {
  title: '知微',                          // 封面大字 + 浏览器标题
  subtitle: '大周永宁十二年，你死过一次。',  // 封面副标题
  tagline: '重生 · 宫斗 · 多结局',          // 封面小字
  version: '1.0',                         // 随便写
}
```

---

## stats —— 数值条

```js
stats: [
  { key: '圣宠', init: 0,   min: 0, max: 25,  color: '#d3b073' },
  { key: '银两', init: 100, min: 0, max: 260, color: '#a9906a' },
]
```

| 字段 | 说明 |
|---|---|
| `key` | 变量名，剧本里直接用它加减。**中文可以**，会显示在顶部 |
| `init` | 初始值 |
| `min` / `max` | 硬上下限，同时也是进度条的比例基准 |
| `color` | 进度条颜色，可省略 |

> `max` 不要随手写 100。如果全流程最多只能涨到 40，`max` 就写 40，否则进度条永远只填一小截，玩家会觉得数值没动。
> 用 `npm run validate` 会打印每个数值在所有路径下的真实范围，照着定 `max` 和结局阈值。

---

## nodes —— 节点

一个节点 = 一屏正文 + 若干选项。

```js
a1: {
  chapter: '第一章 · 雪',    // 顶部章节名；省略则沿用上一节
  text: `正文。

空行分段。`,
  effect: { 心计: 3, 银两: -50, flags: ['玉佩'] },   // 进节点时结算，可省略
  choices: [
    { text: '先确认日子。', next: 'a2' },
    { text: '先下床。',     next: 'a3', effect: { 声望: 2 } },
  ],
}
```

### 简写

只有一个「继续」按钮时：

```js
a2: { text: `……`, next: 'a3' }
```

### 正文

用反引号模板字符串，`\n\n` 或直接空行分段。**不要**在正文里写 HTML，会被转义成文本。
正文里出现 `</script` 会让单文件打包失败，真需要就写成 `<\/script`。

---

## effect —— 数值与标记

```js
effect: { 心计: 3, 银两: -50, flags: ['玉佩', '见过太后'] }
```

- 数字键 = 数值增减，自动夹在 `[min, max]` 内
- `flags` = 打标记（布尔），之后用 `has('玉佩')` 判断
- 布尔值也支持：`effect: { 已知真相: true }`

写出没在 `stats` 里定义过的数值名，校验器会报错。

---

## choices 与条件锁

```js
choices: [
  {
    text:   '拉起她的手：「我带你出宫。」',
    next:   'e_free',
    require: "has('玉佩') && 银两 >= 150",
    hint:    '需 玉佩 · 银两 150',
    effect:  { 声望: 2 },
  },
]
```

`require` 里可以用：数值名（中文也行）、`&&` `||` `!` `>=` `<=` `==`、`has('标记')`。

条件不满足时，选项**会显示但置灰**，并带上 `hint`。这样玩家知道自己错过了什么——比直接藏起来更能勾起重玩的欲望。

`hint` 省略时直接显示 `require` 原文，不好看，建议手写。

> ⚠️ **每个决策节点必须留一条不带 `require` 的选项。**
> 全锁死的节点等于让玩家卡死，校验器会直接报错。

---

## ending —— 结局

```js
e_cold: {
  ending: {
    title: '冷宫',                 // 结局名，封面大字
    label: '结局 · 四',            // 上面那行小字
    rank: '下',                    // 徽章，随意（甲上/甲/乙/S…）
    text: `结局正文……`,           // 可长可短，会滚动
    comment: '一句话点评。',        // 结局卡底部的一句话
  },
}
```

结局节点不需要 `choices`。达成后自动记进「已解锁结局」，重开不丢。

---

## 常见错误

| 症状 | 原因 |
|---|---|
| 点选项没反应 | `next` 指向了不存在的 id（校验器会报「指向不存在的节点」） |
| 玩到一半卡死 | 那个节点所有选项都被条件锁住了 |
| 结局永远拿不到 | 数值上限太小，涨不到阈值；或需要的标记和数值互斥 |
| 进度条一直很短 | `max` 设太大了 |

`npm run validate` 会把上面这些都查出来，包括**穷举所有路径**看每个结局能不能真的走到。
**发版前必须绿。**

---

## 文本风格建议

- 一段话别超过 3 行，手机上一屏看不完会疲劳
- 每个节点 120–220 字；长段落拆成两个节点
- 选项要有真实取舍，别做成「好/坏」二选一
- 前三屏必须给冲突，别铺设定
