# 存档系统

**结论：完全不依赖后端。** 引擎里没有任何 `fetch` / `XMLHttpRequest` / `WebSocket` 调用，打包产物里也没有任何外部资源。

代价是存档绑在浏览器上，且**完全不防作弊**。下面说清楚边界，以及什么时候才需要后端。

---

## 三个机制

| 机制 | 存储位置 | 触发时机 |
|---|---|---|
| `localStorage` | 玩家浏览器 | 每进入一个节点就写一次 |
| `pagehide` 兜底 | 同上 | 关页 / 刷新 / 切后台时再写一次 |
| 存档码 | 玩家自己复制的文本 | 手动导出、导入 |

### 键名规则

```
huaben.save.<gameId>    # 进度
huaben.ends.<gameId>    # 已解锁结局
```

`<gameId>` 就是 `games/` 下的文件夹名，例如 `huaben.save.zhiwei`。

**每个游戏独立命名空间**，多游戏不会串档。

### 生命周期

| 事件 | 行为 |
|---|---|
| 进入节点 | 覆盖写入 |
| 达成结局 | **删除进度**，避免「继续上次」读到一个已结束的档 |
| 点「开始 / 重新开始」 | 先删再开新局 |
| 已解锁结局 | 永久保留，重开不丢 |

### 存储健康检查

启动时会做一次探针写入（`__zw_probe__`）。失败则：

- 封面顶部显示红色提示条
- 游戏内顶部显示窄条
- 「载入存档码」按钮出现在封面

**绝不静默失败**。这条是踩过坑才加的：早期版本用空 `catch` 吞掉异常，玩家以为存了，其实一条没写进去。

## 存档码格式

公开格式，任何人可以实现兼容的导入导出：

```
ZW1:<base64(UTF-8 JSON)>
```

JSON 结构：

```json
{
  "v": 1,
  "s": { "圣宠": 20, "心计": 35, "声望": 0, "银两": 160 },
  "f": { "玉佩": true },
  "n": "c5_1",
  "c": "第五章 · 药"
}
```

| 字段 | 含义 |
|---|---|
| `v` | 格式版本，当前 `1` |
| `s` | 数值快照 |
| `f` | 标记（flags） |
| `n` | 当前节点 id |
| `c` | 当前章节名（只影响显示） |

导入时只强校验 `n` 必须是存在的节点，其余字段缺失会用默认值补齐。

> 为什么不带 `log`（已读记录）：完整 log 会让存档码膨胀到几千字符，而回看历史对迁移存档不重要。

## 三个真实限制

### 1. 换设备就没了

存档绑浏览器。换手机、清缓存、开无痕 → 进度消失，除非提前导出了存档码。

### 2. 不能跨设备同步

电脑玩到第五章，手机要从头开始。

### 3. 完全不防作弊

存档码是明文 base64，`atob` 一下就解开了。实测：

```js
// 伪造一个「已到第五章、数值拉满」的存档码
ZW1:eyJ2IjoxLCJzIjp7IuWco+WuoCI6MjAsIuW/g+iuoSI6MzUs...
```

贴进「载入存档码」，结果：

```
载入后章节: 第五章 · 药
数值: 圣宠20 心计35 声望0 银两160
可解锁结局: 3 个可选 / 4 个
```

一步跳过前四章，直接解锁三个结局。打开开发者工具改 `localStorage` 同理。

**base64 不是加密，是编码。**

## 什么时候才需要后端

| 你的模式 | 现在够不够 |
|---|---|
| 免费试玩引流，完整版一次性买断 | ✅ 够 |
| 卖激活码解锁「完整版」 | ⚠️ 够但不牢，改个变量就绕过 |
| 章节付费 / 内购 | ❌ 不够 |
| 运营数据（玩到第几章流失） | ❌ 不够 |
| 跨设备存档、账号体系 | ❌ 不够 |

### 建议

**现阶段别加后端。**

要验证的是「有没有人愿意掏钱」，不是「防住那 1% 会改代码的人」。为 1% 加账号 + 数据库 + 支付 + 运维，成本 80%，收益接近 0。

真要加的时候，前端结构不用改，外面套一层就行：

1. 登录（手机号 / 微信）
2. 服务端存进度，前端启动时拉取
3. 付费内容按会话下发，而不是全量打包在 HTML 里

第 3 点是关键：**只要剧本全文在 HTML 里，任何前端校验都能绕过**。真防盗必须让内容在服务端。

---

## 存档码的正当用途

别只当成漏洞看，它本来就是个功能：

- 玩家换手机迁移存档
- 客服帮玩家补档
- 你测剧本时想直接跳到第五章看效果
- 玩家之间分享存档、做「存档挑战」

要更安全的存档码（防改），加一层签名即可：服务端用私钥对 JSON 签名，前端校验。但这又回到需要后端了。
